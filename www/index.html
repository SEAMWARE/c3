The Data Space Connector: the provider above is the consumer's Keycloak; c³ gets the credential there and presents it to the verifier.

          

            
            

              
              
            

          

          

            
            
          

        

        
Or a token of its own

        

          
          
          

            
            
          

        

        

          
Headers of its own (an API key, Basic auth, what a gateway asks for)

          

          
          
          

            
            
          

          

        

        
The headers go with every request to this broker, as they are; an Authorization among them takes the place of the token. A secret one's value stays in c³'s backend - the page shows its last characters only. The token is sent as Authorization: Bearer with every request to this broker - reads, live values, writes. The broker decides what it allows. A login comes first, and its token is renewed by c³ until the provider ends the session; the provider's client must be a public one that allows http://<c³>/api/oidc/callback as a redirect URI. Without a login or a token of its own, a broker gets c³'s default: --token-file, else $C3_TOKEN.
