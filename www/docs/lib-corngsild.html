corNgsild

The NGSI-LD library (SEAMWARE/corNgsild): what an NGSI-LD body may hold and what it means, the three representations of an entity, the q, scopeQ, type and geo languages, the subscription and registration caches, the notifications and the distributed operations. It plugs into corRest as a set of request hooks and leaves storage to the broker - coraine is the broker built on it.

Where it sits

corNgsild is the largest of the libraries - 118 headers, 101 source files. Below it are corRest (the request, its arena, the HTTP client) and corJsonld (the @contexts and the expansion); above it, the broker supplies what it does not own:

The umbrella header corNgsild/corNgsild.h includes the most used ones; the rest are included one by one. The map of every header by area is at the end.

The per-request state

Everything the hooks learn about a request lands in one struct, CorNgsild (CorNgsild.h), read as corNgsild.<field> anywhere: the URL parameters as sent and as parsed (q and qExpr, type and typeExpr, scopeQ and scopeExpr, pick and pickTree, georel and geoRel, orderByV, the temporal parameters, format, ...), the request's @context (contextP, userContextUrl), its tenant (tenantP, the broker's type, opaque here), and the per-request queues.

#define corNgsild (*corNgsildBind())

static inline CorNgsild* corNgsildBind(void)
{
  CorNgsild* p = (CorNgsild*) corRest.userData;
  return (p != NULL) ? p : &corNgsildFallback;
}

It belongs to the connection: corRest creates one per connection through the user-data hooks and binds it with the connection's corRest, so a request served on a worker thread, or resumed on another, sees its own. A thread with no connection - the periodic loop, a bridge's thread - gets a per-thread fallback; such a thread calls corNgsildFallbackRelease() before it ends.

Core terms: the CorTerm enum

Every term of the core context v1.9 has an id, CorTerm (CorTerm.h): CorTermId, CorTermType, CorTermObservedAt, ... in the core context's own order, then the terms coraine adds to the core. The id travels on the node - CorNode.termId - and on the corJsonld item, so which core term a member is costs no string compare.

A term id says what a node's NAME is, not where it sits: an observedAt inside a compound value is CorTermObservedAt too. The KJF_* bits corJsonld sets during expansion (corJsonld) are the other half.

Checking a payload

bool ldCheckEntity(CorNode* entityP, LdOp op, CorNode* dbEntityP, CorAlloc* faP);
bool ldCheckAttribute(CorNode* attrP, LdOp op, LdAttrType attrTypeFromDb, CorAlloc* faP);
bool ldCheckSubscription(CorNode* subP, LdOp op, bool merged, LdFormat* notifFormatP, CorAlloc* faP);
bool ldCheckRegistration(CorNode* regP, LdOp op, bool merged, CorAlloc* faP);

Smaller ones - ldCheckGeo, ldCheckDateTime, ldCheckUri, ldRegexValid - are called by these and by the service routines. A check takes the expanded, normalized tree and the operation (LdOp, one bit per NGSI-LD operation, § 4.20); an update passes what is stored. It answers true, or false with the error already raised:

ldError(400, LD_ERROR_BAD_REQUEST_DATA, "Invalid Array Entry", "entity id is missing or not a string");
return false;

ldError is a macro (ldError.h): status, type, title and a printf-style detail into corRest.out, logged with the caller's file, line and function. The type URIs are in LdProblem.h; LdCheck.h has the one-line checks (OBJECT_CHECK, STRING_CHECK, URI_CHECK, DUPLICATE_CHECK, ...) that raise and return in one statement. A batch collects per-entity errors in an LdBatchErrorList.

Before any check, the parse hook has made the body normalized: ldNormalizeInput turns every concise or simplified Attribute into an object with its type and its value key. A Merge leaves the bare values of a body declared simplified (?format=simplified) to ldEntityMerge, which shapes them after the stored Attribute.

The storage model

The library defines the form the broker stores an entity in and converts both ways:

void ldApiEntityToDbModel(CorNode* entityP, CorAlloc* faP, int64_t createdAt);   // API -> storage
void ldEntityToApi(CorNode* entityP, CorAlloc* faP);                             // storage -> API
"temperature": { "@none":    { "type": "Property", "value": 21, "createdAt": ..., "modifiedAt": ... },
                 "urn:ds:1": { "type": "Property", "value": 22, ... } }

Every Attribute is an object keyed by datasetId, @none for the default instance; timestamps are epoch nanoseconds; names are expanded, core terms short. createdAt 0 stamps now; a Replace passes the stored entity's. On this form work ldEntityMerge (Merge Entity, with an LdMergeReport of what changed and why - which drives the notification triggers), ldEntityFragmentApply (Replace and Append), ldEntityAttrsSet, and the subscription matchers.

A q's tree (LdQ.h) is what a database plugin translates for its own query; ldQStripLinked gives the part it can evaluate (no linked-entity terms), ldQAttrs every attribute a q names, ldQRender / ldQRenderStored a q back to a string, compacted for a response or expanded for storage. ldExpandParams expands the names of the vocabulary-bearing URL parameters (type, pick, omit, attrs, geoproperty, ...) once the request's @context is known, ldQueryBodyToParams reads a § 5.2.23 Query body into the same fields.

An EntityMap (LdEntityMap.h, ldEntityMap.h) freezes the result set of a query - which entity ids, from which sources - so later pages come from it; all maps of the broker together are capped by ldEntityMapMaxBytes (--entityMapMemory). A Snapshot (LdSnapshotCache.h) freezes the values.

Subscriptions and the sub cache

Each tenant has an LdSubCache (the broker creates it, ldSubCacheCreate()) - and a second one for Context Source Registration subscriptions. An item is the subscription tree plus everything a match needs, parsed once: the entity selectors, the watched attributes (an attr@datasetId entry names one instance), q, scopeQ, geoQ, the trigger mask, the notification's projection, status and counters.

Subscriptions with timeInterval are in their own cache (LdPernotCache.h), which no write walks; ldPernotLoopStart runs them on the periodic loop through the broker's query callback. A subscription with throttling buffers its matches in a coalesce-to-latest set (ldThrottleDirty.h), flushed by ldThrottleFlushStart's tick.

Notifications

A write does not notify while it runs. Its service routine queues each changed entity:

ldNotifyDefer((LdSubCache*) tenantP->subCacheP, entityP, LdNotifyEntityCreate, NULL);   // or a merge report

and after the response has gone out the broker's post-response hook calls ldNotifyDispatchPending(): ldSubscriptionNotifyBatch matches the queue against the candidates and sends one notification per subscription, its data every entity of the request that matched, in order. The entity must stay valid until then - the request arena or the store's copy. ldSubscriptionUpdateMayMatch lets a PATCH skip reading the entity back when no subscription can be notified.

EndpointSent by
http://, https://corNgsild, a POST through corRest's client
mqtt://, mqtts://, ...the hooks installed with ldNotifyTransportSet(hasFn, sendFn) - coraine's bridges. With none, such a subscription is refused
urn:ngsi-ld:selfthe hook of ldNotifyStreamSet(putFn) - coraine's server-sent events; compiled only with COR_WITH_EVENT_STREAM=1, the default

A subscription's notification.endpoint.receiverInfo becomes the notification's headers through ldReceiverInfoHeadersAdd(reqP, receiverInfo, fromRequest), on every path that sends one: Authorization and the like pass; Content-Type, an @context Link, Prefer, NGSILD-Tenant and NGSILD-Snapshot are the broker's own and are skipped. A value urn:ngsi-ld:request takes the triggering request's header with fromRequest true, and is left out without one (a periodic tick, a notification re-dispatched from a Context Source).

Three more hooks: ldNotifyFilterHook removes the entities a subscriber may not read (coraine's auth plugin; a notification left empty is not sent), ldNotifyStatsHookSet counts each send, ldLinkedEntitiesHookSet does a notification's join. The counters (timesSent, lastFailure, ...) go to the store through ldStatsFlushLoopStart, a thread of its own.

The periodic loop

ldPeriodicLoop.h: one thread that calls each registered tick once a second, in the order they were registered, at most 8, each with a scratch arena reset before it. Register with ldPeriodicLoopRegister(fn, ctx) before ldPeriodicLoopStart(). On it run the periodic subscriptions, throttling, the periodic CSR notifications and the reaper of volatile contexts.

Registrations and the reg cache

Each tenant also has an LdRegCache (ldRegCacheCreate()): its Context Source Registrations, each parsed once into its RegistrationInfo (entity ids, id patterns, types, property and relationship names), its LdRegMode (inclusive, exclusive, redirect, auxiliary), the operations it supports (LdOp bits; a § 4.20 group name is its member bits), its counters.

int  ldRegCacheMatchForRetrieve(LdRegCache* cacheP, const char* entityId, char** entityTypeV,
                                LdRegMode modeFilter, LdRegCacheItem*** matchVP);
int  ldRegCacheMatchForQuery(LdRegCache* cacheP, char** entityIdV, const char* idPattern,
                             char** entityTypeV, LdRegMode modeFilter, LdRegCacheItem*** matchVP);
void ldRegCacheMatchRelease(LdRegCacheItem** matchV, int n);

A matcher walks under the read lock, pins each match and returns them; the caller forwards to them without the lock and then calls ldRegCacheMatchRelease - never free(matchV). A dispatcher asks once per mode (exclusive, redirect, inclusive) and sequences the passes. Writers take ldRegCacheWrLock.

Around the cache: ldCsrSubNotify.h - subscriptions to registrations and their CsourceNotifications; ldDiscovery.h - § 5.10.2 discovery; ldProbeSourceIdentity.h - a new registration's /info/sourceIdentity, probed after the response (ldRegCacheProbePending).

Distributed operations

All of it is behind one flag, ldDistributed (--distributed): off, the forwarding matchers find nothing and every operation stays local; the Registry API works either way.

Part
ldDistOpSendReceive, ldDistOpSendMultione forward, or a fan-out: headers built (Via, NGSILD-Tenant, the registration's contextSourceInfo), the registration's timeout, its counters updated. In a fan-out the HTTP forwards are in flight together (corRest's multi client), with them those of a plugin that has start/wait; another plugin's go one at a time after them; a registration that points back at this broker is served in-process
LdForwarding.h, ldForwarding.hthe transports: a plugin (LdForwardingPlugin: alias, URL schemes, send, optional start/wait) registered with ldForwardingRegister; the first to claim a scheme keeps it. coraine registers http/https and cor://
ldCsourceAlias.h, ldDistOpLoopDetectedloops: this broker's per-tenant alias in the Via header (--csourceAlias); a forward that would come back is not sent
ldDistOpForwardContextthe @context a forward to this registration uses - its jsonldContext
ldEntityFragment.h, ldWriteResult.ha write split by RegistrationInfo; the answers merged into one UpdateResult
ldDistMerge.hversions of one entity from several sources merged (§ 4.5.5.3)
ldDistSub.ha subscription forwarded to the matching sources as subordinates, kept in step on PATCH and DELETE of the subscription and on registration changes; their notifications come back to ldBrokerHttpEndpoint. A new registration gets the subordinates of the subscriptions it matches (ldDistSubOnRegCreate), a deleted one loses them (ldDistSubOnRegDelete), and a PATCHed one (§ 10.5.2.4, ldDistSubOnRegUpdate) is compared before and after: a subordinate still matching at the same endpoint and tenant has its entities PATCHed at the source when they changed; one no longer matching (the type, the operations, a Via loop) or whose registration moved endpoint or tenant is DELETEd where it was; one matching now with no subordinate is POSTed. None of it without --distributed

ldSplitEntities (--noSplitEntities turns it off) decides whether a distributed query assembles entities from parts held by several sources, or takes each entity whole from one.

Using it in a broker

coraine's startup (src/lib/startup/startupCoreContext.c, src/app/coraine/coraine.c), in order:

corLdInit(&contextAlloc, NULL, startupContextDownload, startupContextError);   // corJsonld
bridgeCoreTermsAdd(&contextAlloc);          // coraine's terms into the core ...
ldExtensionTermsAdd(&contextAlloc);         // ... and those of its NGSI-LD extensions
ldCoreTermIdsInit(&contextAlloc);           // every core term its CorTerm
ldInit();                                    // URL parameters and hooks into corRest; corJsonld's callbacks

// per tenant
tenantP->subCacheP    = ldSubCacheCreate();
tenantP->pernotCacheP = ldPernotCacheCreate();
tenantP->regCacheP    = ldRegCacheCreate();
tenantP->regSubCacheP = ldSubCacheCreate();

ldForwardingRegister(&httpPlugin);          // forwarding transports
ldNotifyTransportSet(transportHas, transportSend);
ldNotifyStreamSet(streamPut);
corRestSetPostResponseHook(brokerPostResponseHook);   // calls ldNotifyDispatchPending(), ...

ldPernotLoopStart(brokerPernotCaches, pernotQueryCallback);
ldThrottleFlushStart(brokerTenantCaches, throttleRetrieveCallback);
ldCsrSubPeriodicLoopRegister(brokerTenantCaches);
ldContextHostReaperStart();
ldPeriodicLoopStart();
ldStatsFlushLoopStart(subStatsFlushInterval, subStatsFlushAll);

The routes carry their operation and accepted parameters (coraine's ngsildServices.c):

{ CorVerbPost, "/ngsi-ld/v1/entities", postEntities, LD_PARAMS_POST_ENTITIES, LdOpCreateEntity },

Globals the broker sets from its options before it serves: ldDefaultContextUrl (--defaultUserContext), ldDistributed, ldSplitEntities, ldCsourceAliasBase, ldBrokerHttpEndpoint (--httpEndpoint), ldNotifyValueChangeOnly (--notifyValueChangeOnly), ldDefaultCooldownNs (--cooldownMillis), ldTimestampHighPrecision (--high-precision), ldEntityMapMaxBytes, ldContextSourceExtras. Code with no request to take a context from - a configuration file, a sample on a bridge, a cache rebuilt from the store - expands with ldDefaultContext(kaP), not the core alone.

Rules

  • Read a node's term with ldTermId, rename it with ldNodeRename.
  • Raise with ldError and return false; the render hook turns corRest.out into the ProblemDetails.
  • Hold no cache lock across a send: pin, unlock, send, unpin. Registration lock before subscription lock.
  • A thread that is not corRest's and calls the library sets up its own corRest arena (as the periodic loop does) and calls corNgsildFallbackRelease() before it ends.
  • Trace levels are 200-240 (ldTraceLevels.h); a new one takes 241 and up, below corAlloc's 300-303.
