corTree - the tree

The in-memory tree every part of coraine works on (SEAMWARE/corTree): the node, CorNode, and the functions that build, edit, search, clone, sort and free a tree of them. It parses and renders nothing - JSON in and out is corJson; the binary cor format (corTreeBin.h) is another producer and consumer of the same tree.

The node

typedef struct CorNode
{
  char*            name;     // NULL or "" for an array item
  struct CorNode*  next;     // the next sibling
  CorValueType     type;     // CorString, CorInt, CorFloat, CorBoolean, CorNull, CorObject, CorArray
  unsigned char    flags;    // for the users of the library - opaque to corTree
  unsigned char    kind;     // what an object is, for the users of the library - opaque to corTree
  uint16_t         termId;   // for the users of the library - opaque to corTree
  CorValue         value;    // b, i, f, s - or, for a container, head and tail. LAST
} CorNode;

A tree is nodes linked by next: a container (CorObject, CorArray) holds the first and the last of its children in value.head and value.tail, and each child points to the next. A child does not know its parent. An array's items have no name; an object's members are kept in the order they were added - corTree never reorders a container unless asked (Sorting).

TypeValue
CorStringvalue.s, a char*
CorIntvalue.i, a long long
CorFloatvalue.f, a double
CorBooleanvalue.b
CorNullnone
CorObject, CorArrayvalue.head, value.tail - NULL for an empty one

CorNone (0) is no type: a node is never built with it. corTreeValueType(type) names a type, corTreeValue(nodeP, buf, bufLen) gives a node's value as text.

flags, kind, termId

Three fields corTree carries and never reads: they belong to the code that uses the tree. In coraine, termId is which NGSI-LD core term a name is (0: none), kind what an object is - an attribute's type (0: a plain object) - and the cor format writes both instead of the strings they stand for (cor://). flags is bits for any user.

Every builder zeroes all three (and sets next to NULL), and corTreeClone copies all three. Code that builds nodes without the builders - a parser, a database reader - must do the same, or what a node is taken for depends on which code path made it.

The layout - 40 bytes, and 32

This is the prefix layout: value is last, and its last 8 bytes, value.tail, are a container's only. A node that is not a container can therefore be allocated without them - 32 bytes - and the trees that live on are: corTreeClone(NULL, ...), the clone into the tree heap, allocates every scalar so. Every builder allocates 40.

A 32-byte node is never made a container in place, and never copied whole. *a = *b from a 32-byte node reads 8 bytes it does not have; turning it into an object writes value.tail past its end. corTreeNodeCopy(toP, fromP) copies the bytes fromP has (shallow: a container's copy shares its children). A change of size is a new node, put where the old one was - corTreeChildReplace.

The layout's number

The layout has a number, corNodeLayout - 2 - which every object built with CorNode.h carries (a weak, exported symbol), and every object built with it also references corNodeLayout2, which only a corTree with this layout defines. A plugin built against another layout than its broker is refused either way, instead of reading every node at the wrong offsets: a broker refuses a plugin with another number (corPlugin), and a broker older than layout 2 fails the plugin's dlopen with undefined symbol: corNodeLayout2 (Plugin architecture). A change of the layout is a new number and a new symbol name.

Each builder allocates one block: the node, then its name, then - a string's - its value, both copied in. The first argument is where the block comes from:

kaPThe blockFreed
a CorAlloc* (corAlloc)carved from the allocator's bufferswith the allocator, all at once - never node by node

In coraine a request's trees - its parsed body, its response - are built in the request's allocator, corRest.kallocP, and go with it. This is GET /admin/config's response, one object per option:

CorAlloc* allocP = corRest.kallocP;
CorNode*  root   = corTreeObject(allocP, NULL);
CorNode*  optsP  = corTreeArray(allocP, "options");

CorNode* oP = corTreeObject(allocP, NULL);                   // an array item: no name
corTreeChildAdd(oP, corTreeString(allocP, "name", aP->longName));
corTreeChildAdd(oP, corTreeString(allocP, "type", typeName(aP->type)));
if (aP->secret)
  corTreeChildAdd(oP, corTreeBoolean(allocP, "secret", true));
corTreeChildAdd(optsP, oP);

corTreeChildAdd(root, optsP);
corRest.out.responseTree = root;

A builder returns NULL when it gets no memory. corTreeString of more than 16 KiB that gets none returns a string node "too big string" instead.

corTreeChildAddOrReplace(container, name, nodeP)appends nodeP, or - when the object has a member of that name - puts nodeP in that member's place. The old member is not overwritten: it is returned, out of the tree, for the caller to free (NULL when nodeP was added)

corTreeChildAdd is not a move. It sets child->next to NULL: a node still in another container cuts that list short after it, and leaves the other container's tail pointing into this one. Unlink it first, or use corTreeChildMove. A node is in one container at a time.

Cloning

CorNode* corTreeClone(CorAlloc* kaP, CorNode* nodeP);

A deep copy of a node and everything under it, with flags, kind and termId; the clone has no next. Into an allocator, every node is a builder's - 40 bytes. Into the tree heap (kaP NULL), a scalar is 32 bytes. This is how a request's tree becomes one that outlives the request - a Snapshot's filter, a subscription patched into the cache:

CorNode* clone = corTreeClone(NULL, fP);   // long-lived: the request's allocator goes with the request

corTreeCloneMarked(kaP, nodeP, mask, fn, ctx) clones the same way, except that a container whose flags have a bit of mask, or that has a kind, is cloned without them and fn(kaP, copyP, origP, ctx) is called on its clone, after its children - for a user that keeps something in a mark the clone must get back as members, in the clone's own pass.

The tree heap

The trees that live on - corDB's entities, the subscription, registration and snapshot caches - are built with no allocator (NULL) and live in the tree heap, corTreeHeap.c:

  • One block per node - the node, its name and a string value - as with malloc, but 8-byte aligned and with no header: blocks of one size (8 to 1024 bytes, in steps of 8) carved from 16 KiB pages that each hold one size.
  • A free reads nothing in the node. It finds the size by the page the address is in, so a node whose name or value was changed after it was built is freed as what it was allocated as. A freed block goes on its size's free list and is the next one of that size handed out; pages are not given back to the system.
  • Addresses, not RAM. At the first allocation the heap reserves 64 GiB of addresses (half of that, and so on, down to 256 MiB, where less can be had), MAP_NORESERVE: what is resident is what is used. The untouched part is kept out of a core dump.
  • Threads: a cache per thread. Each thread keeps its own free blocks of each size and takes and frees them with no lock. A size's mutex is taken only for a batch - 4 KiB worth of blocks, 32 at most (32 blocks of up to 128 bytes, 4 of 1024) - from its free list or, else, a range of its page, and to give a batch back when a thread holds two batches. That is at most 8 KiB per size per thread. A thread that ends gives its cache back; the blocks stay in the heap, for the other threads.

Freeing

void corTreeFree(CorNode* nodeP);

Frees a node and everything under it, block by block. It is for trees in the tree heap - built or cloned with NULL. A tree in an allocator is never freed node by node: it goes when the allocator is reset.

Unlink before freeing. corTreeFree does not take the node out of its container - a member freed in place leaves its container pointing at freed memory. corTreeChildRemove it first. And a heap tree must not have an allocator's node grafted into it (or the reverse): corTreeFree would hand that node to free().

corTreeChildRemove(cacheP, oldP);   // out of the tree first
corTreeFree(oldP);
