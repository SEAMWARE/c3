corNgsild - most of the NGSI-LD rules, 12k lines - is the best-covered. corRest and corJsonld do not know which database is underneath, and barely move between the runs; the difference is coraine/src and, through the 56 mongoc-only tests against corDB's 6, corNgsild.

Branches is the number to move. A line is covered if it ran once: if (a && b) that only ever runs with both true is a covered line and two uncovered branches - and the second case is where untested behaviour hides. Hence branch coverage close to twenty points below line coverage.

A rise is not always a new test. Dead code removed raises the percentage too, and the headline cannot say which. Read the numerator: if it has not moved, nothing new is tested.

Two runs, two measurements

A test that pins a backend-specific answer - MongoDB's earth model in the fourth digit of a distance, the tenant-wide 2dsphere index that keeps a GeoProperty and a Property from sharing an attribute name - declares REQUIRE_DB and belongs to one run only: 634 tests on mongoc, 584 on corDB. Each report leaves out the database plugin not under test - a corDB run cannot execute a line of mongoc.so.

So a mongoc run's never-entered functions include ones only the corDB path reaches, and the other way round: geoEntityValidate is called only from corDB, attrInstanceOf only when the broker evaluates q itself. A zero in one run is a property of the run, until its caller is followed.

The figure depends on the environment

The HA cache sync (--high-availability mongo) rides a MongoDB change stream, which reads the oplog - a standalone mongod has none. corTestParams.sh probes for a replica set: on one, ha_cache_sync.test is in the run; on a standalone it is not, and nothing in the output says so. Against a standalone the HA code (108/149 lines, 10/10 functions, 72/114 branches) reads as unexecuted: -0.34 pp on lines, -0.73 pp on functions, -0.26 pp on branches.

The figures above are from a single-node replica set. So are the CI jobs that run the suite (ci.yml's functest matrix, the nightly's coverage and valgrind jobs - quay.io/seamware/mongo-rs, mongo:8.2 with --replSet). Two jobs stay on a standalone: perf, whose comparison with recorded history an oplog would shift, and ETSI, which has no HA test.

Reproducing it

make coverage                # mongoc  - coverage-mongoc/index.html
make coverage DB=corDB       # corDB   - coverage-corDB/index.html
make coverage-etsi           # the ETSI test suite - coverage-etsi/index.html

The ETSI target instruments the broker, the NGSI-LD libraries and the mongoc and timescale plugins. Each of these gives a wrong number when it is missed:

  1. The coverage tree is built from scratch - a .gcno of a renamed or deleted source otherwise reports a vanished file as unexecuted.
  2. SEAMWARE_PLUGIN_DIR is exported beside COR_PLUGIN_DIR - without it a test's --apiPlugins admin loads the installed, uninstrumented admin.so, and the admin plugin reads 0 %.
  3. gcovr >= 8.3 with --gcov-ignore-parse-errors=negative_hits.warn_once_per_file - gcov can report a negative hit count in a threaded binary (GCC bug 68080); without the flag gcovr drops the whole file from the report and exits 0.
  4. The libraries are instrumented, and the root is the sibling directory - otherwise they link in without counters and leave both sides of the fraction.
  5. The flags go in EXTRA_CFLAGS, never DFLAGS - DFLAGS on the command line replaces a library's own defines; EXTRA_CFLAGS is appended last.
  6. The mongod is a replica set - a single node is enough: mongod --replSet rs0, then rs.initiate() once.

The libraries stay instrumented afterwards. make libs-rebuild takes them back; make libs does not - it is incremental, and a change of compiler flags is invisible to it.
