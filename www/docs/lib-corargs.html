corArgs - command-line options

A program declares its options in one table - name, type, default, limits, description - and corArgs fills the variables from the defaults, the environment and the command line, checks every value against its type and its limits, and prints the usage. coraine, coraine-import and every plugin's own options go through it. Repository: SEAMWARE/corArgs.

The option table

An option is a CorArg; a table is a vector of them ending with CORARGS_END. Every field that is not a name or a pointer to the variable is a void* holding the value itself - the _vp macro is the cast. This is coraine's own --port:

#include "corArgs/corArgs.h"

unsigned short port = 0;

static CorArg kargV[] =
{
  { "--port", "-p", CorArgUShort, _vp &port, CorArgOpt, _vp 1026, _vp 1, _vp 65535, "TCP port to listen on" },
  ...
  CORARGS_END
};
FieldWhat it is
longName, shortName"--port", "-p" - matched as whole words. A short name may be longer than one letter (-db, -corPort); only a one-letter Bool can be part of a group. Either may be NULL, not both.
typethe variable's type - the table below. corArgs stores through a pointer of that type, so the variable must be exactly it: a CorArgBool's is a bool, a CorArgUShort's an unsigned short.
valuePthe variable; NULL is refused
sortCorArgOpt (optional), CorArgReq (required - refused when neither the command line nor the environment sets it), CorArgHid (hidden: accepted, never listed by -u or -U)
defthe default, written into the variable by corArgsInit - a number cast to the pointer, a string as the pointer itself
min, maxthe limits - whole numbers for an integer or a CorArgFloat option, strings for a CorArgString option (compared with strcmp); CORARGS_NL is no limit
descriptionthe usage text; NULL is refused
TypeVariableAlso named
CorArgBoolbool
CorArgChar, CorArgUCharchar, unsigned charCorArgInt8, CorArgUInt8
CorArgShort, CorArgUShortshort, unsigned shortCorArgInt16, CorArgUInt16
CorArgInt, CorArgUIntint, unsigned intCorArgInt32, CorArgUInt32
CorArgLong, CorArgULonglong long, unsigned long longCorArgInt64, CorArgUInt64
CorArgFloatfloat
CorArgStringchar* - pointed at the argument, not copied

An integer is decimal, or hexadecimal (0x1F, H'1F), octal (O'17) or binary (B'101). The whole text must be the number: 12x is refused, not read as 12.

Limits are pointers too. NULL as min is the number 0, not "no limit": an int option with min NULL refuses -1. Write CORARGS_NL for no limit. A CorArgFloat's default and limits are whole numbers - the pointer holds a long long: _vp 1, _vp 1, _vp 10 is a default of 1.0 and a range of 1.0-10.0. A CorArgString's limits are strings, and for a string NULL is no limit, as CORARGS_NL is: with _vp "050" and _vp "100", 060 is accepted and 200 refused. A value outside its limits is refused on the command line and in the environment alike.

What corArgsInit checks

Before anything is set, the table itself: an option with no name, a name used twice or taken by a builtin (--usage, -u, --Usage, -U, --verbose, -v), a limit or a default outside the type's range (256 for a CorArgUChar), min above max, an integer option's default outside its limits (one limit alone too; an option with no default, CORARGS_NL, is not checked), a NULL valueP or description, a type or sort out of its enum. Each is CorArgsBadParam or CorArgsNameTaken, with the option named in the error list (corArgsErrorGet()), and nothing is set. A CORARGS_SEPARATOR has no name and no variable, and is accepted.

Init, add, parse

CorArgsStatus corArgsInit(const char* progName, CorArg* kargV, const char* prefix);
CorArgsStatus corArgsAdd(CorArg* kargV);
CorArgsStatus corArgsParse(int argC, char* argV[]);
  1. corArgsInit checks the table, builds the option list - the builtins first, then the table - writes every default into its variable and then every value the environment holds.
  2. corArgsAdd, any number of times between the two, appends a table: its defaults and its environment values are applied the same way. The table is not copied and must stay valid. This is how coraine adds a plugin's options - it loads the plugins between corArgsInit and corArgsParse, so coraine --database corDB -u lists corDB's options (Plugin architecture).
  3. corArgsParse reads the command line: an option there overrides its default and its environment value.

The order of precedence is: the command line, then the environment, then the default. Each option remembers where its value came from (CorArgInfo.from: CorArgFromDefaultValue, CorArgFromEnvVar, CorArgFromShortOption, CorArgFromLongOption).

The option list is corArgInfoV (corArgs/corArgsInit.h), a CorArgInfo per option ending with a CorArgEnd type - the names, the type, the variable, the default, the limits, where the value came from, the environment variable's name and whether it is secret. coraine's GET /admin/config lists every option from it, and its crash report masks the secret ones.

A whole program

#include <stdio.h>
#include <stdbool.h>
#include "corArgs/corArgs.h"

static unsigned short port    = 0;
static char*          host    = NULL;
static int            timeout = 0;
static bool           dryRun  = false;
static bool           keep    = false;

static CorArg argV[] =
{
  { "--port",    "-p", CorArgUShort, _vp &port,    CorArgOpt, _vp 8080,        _vp 1,     _vp 65535, "TCP port to listen on" },
  { "--host",    "-H", CorArgString, _vp &host,    CorArgOpt, _vp "localhost", NULL,      NULL,      "host to listen on" },
  CORARGS_END
};

static CorArg runArgV[] =
{
  CORARGS_SEPARATOR("run options:"),
  { "--timeout", "-t", CorArgInt,    _vp &timeout, CorArgOpt, _vp 30,          _vp 1,     _vp 300,   "request timeout in seconds" },
  { "--dryRun",  "-n", CorArgBool,   _vp &dryRun,  CorArgOpt, _vp false,       _vp false, _vp true,  "say what would be done, do nothing" },
  { "--keep",    "-k", CorArgBool,   _vp &keep,    CorArgOpt, _vp false,       _vp false, _vp true,  "keep the temporary files" },
  CORARGS_END
};

int main(int argC, char* argV2[])
{
  CorArgsStatus ks;

  if ((ks = corArgsInit("myserver", argV, "MYSERVER")) != CorArgsOk)  { printf("init: %s\n",  corArgsStatus(ks)); return 1; }
  if ((ks = corArgsAdd(runArgV)) != CorArgsOk)                         { printf("add: %s\n",   corArgsStatus(ks)); return 1; }
  if ((ks = corArgsParse(argC, argV2)) != CorArgsOk)                   { printf("parse: %s\n", corArgsStatus(ks)); return 1; }

  printf("port %u host %s timeout %d dryRun %d keep %d verbose %d\n",
         port, host, timeout, dryRun, keep, corArgsBuiltinVerbose);
  return 0;
}
gcc -I.. -o myserver myserver.c ../corArgs/libcorArgs.a ../corBase/libcorBase.a

The libraries are sibling checkouts: a consumer compiles with -I.. and links ../corArgs/libcorArgs.a - make leaves the archive there, and make install copies nothing. The only dependency is corBase.

-u and -U

Three options are built in: --usage/-u (the usage), --Usage/-U (one row per option) and --verbose/-v, a Bool read through corArgsBuiltinVerbose - coraine turns its info and verbose log lines on with it. There is no --debug: the trace levels of corLog are what shows more.

$ ./myserver -u
Usage: myserver  [--usage/-u (usage)]
                 [--Usage/-U (extended usage)]
                 [--verbose/-v (verbose mode)]
                 [--port/-p <TCP port to listen on>]
                 [--host/-H <host to listen on>]

                 run options:
                 [--timeout/-t <request timeout in seconds>]
                 [--dryRun/-n (say what would be done, do nothing)]
                 [--keep/-k (keep the temporary files)]

An optional option is in [brackets], a required one is not; a Bool's description is in (parentheses), a value's in <angle brackets>. -U lists the long name, the short name, the environment variable, the sort, the type and the default (- for none, (secret) for a secret option that has one):

$ ./myserver -U
  --usage   (-u)                  Optional   Bool     false
  --Usage   (-U)                  Optional   Bool     false
  --verbose (-v) MYSERVER_VERBOSE Optional   Bool     false
  --port    (-p) MYSERVER_PORT    Optional   UShort   8080
  --host    (-H) MYSERVER_HOST    Optional   String   localhost
  --timeout (-t) MYSERVER_TIMEOUT Optional   Int      30
  --dryRun  (-n) MYSERVER_DRYRUN  Optional   Bool     false
  --keep    (-k) MYSERVER_KEEP    Optional   Bool     false
  • Anywhere on the command line, before anything else. corArgsParse looks for -u and -U first, walking the arguments as the parse does (a value is skipped, so --host -u is a host name), and prints the list before any option is set - so ./myserver -u -p 0, or a bad value in the environment, still prints it.
  • Then it exits, with code 0. corArgsConfig(CorArgsExitOnUsageExitCode, "2") changes the code; corArgsConfig(CorArgsExitOnUsage, "no") makes corArgsParse print the list after the parse and return.
  • A separator - CORARGS_SEPARATOR("title") - is a heading line in the -u list and nothing in -U. It goes in the table given to corArgsInit or corArgsAdd. coraine puts one before each plugin's options: bridge (mqtt) plugin options:.

Switch groups

One-letter Bool options can be given together, as in ls -ltr: ./myserver -nk is -n -k, -nv is --dryRun --verbose, and -nu asks for the usage.

  • Every letter of the group must be the whole short name of a CorArgBool. A short name that only begins with the letter (-db) or an option that takes a value is not one: a group with such a letter is unrecognized option.
  • A letter twice is refused, and the program exits 1: myserver: repeated boolean option: -n.
  • An argument is a group only when it matches no option by name first - -db is coraine's --database, never -d -b.

The environment

Every option except the action options can be set from an environment variable. Its name is the prefix given to corArgsInit, then the option's long name (the short name if it has none) without the leading -, upper-cased, every character other than a letter, a digit or _ turned into _: with the prefix MYSERVER or MYSERVER_, --port is MYSERVER_PORT and --no-browser MYSERVER_NO_BROWSER. coraine's prefix is CORAINE: CORAINE_PORT, CORAINE_DBDIR (a plugin's option, added by corArgsAdd). -U lists every name.

MYSERVER_PORT=7000 MYSERVER_DRYRUN=on ./myserver
port 7000 host localhost timeout 30 dryRun 1 keep 0 verbose 0
  • The action options have none - --usage, --Usage and a program's own --version: they do something and exit, and a variable left in the environment would make every start do it. They are listed by -U with an empty variable column, and are never required.
  • A value is checked as the command line's is - type, range and limits; a number that is not one is refused, not read as 0.
  • The first refused value stops the reading, and is said by corArgsParse - after its -u/-U check, so MYSERVER_PORT=0 ./myserver -u prints the usage - which then returns its status:
$ MYSERVER_TIMEOUT=500 ./myserver
myserver: value 500 for option '--timeout' exceeds its upper limit. Allowed range: 1-300
myserver: (from the environment variable MYSERVER_TIMEOUT)
parse: int out of max limit

A Bool's values

ValueThe option is
true, True, TRUE, on, On, ONon
false, False, FALSE, off, Off, OFFoff
anything else - yes, 1, tRuE, an empty valuerefused: the program does not start
$ MYSERVER_DRYRUN=yes ./myserver
myserver: MYSERVER_DRYRUN=yes: not a Bool - on: true, True, TRUE, on, On, ON; off: false, False, FALSE, off, Off, OFF
parse: invalid value

On the command line a Bool takes no value: present is on. A Bool whose default is true can be turned off only through its environment variable.

Reading one option early - corArgsPeek

char* corArgsPeek(int argC, char* argV[], CorArg* kargV, char* optLongName);

The value of one option on the command line, before corArgsInit or corArgsParse: optLongName (a long or a short name) is looked up in kargV and the builtins, and argV searched for either of its names. It returns the argument after it, "SET" for a Bool, NULL when the option is not there. It reads argV and nothing else - not the environment.

coraine uses it twice: --version is answered before corArgsInit, so a broken installation can still say what it is; and the plugin options (--database, --troe, --apiPlugins, --bridges, --auth) are peeked between corArgsInit and corArgsParse to know which plugins to load - falling back to the variable corArgsInit filled from the environment:

char* dbPeek = corArgsPeek(argC, argV, kargV, "--database");

Secret options

bool corArgsSecret(const char* longName);

Marks an option, after it is declared, as one whose value is never shown - a password, a URI that may hold one. -U shows its default as (secret); coraine's GET /admin/config shows *** and the crash report masks it. coraine's mongoc plugin marks --dbPwd and --dbURI, the timescale plugin --troePwd. false: no option has that long name.

How errors are reported

A function returns a CorArgsStatus - CorArgsOk or what went wrong (CorArgsValueMissing, CorArgsInvalidValue, CorArgsOutOfBounds, CorArgsIntOutOfMaxLimit, CorArgsNameTaken, ...); corArgsStatus(ks) is its text. Beside the status:

WhatWhere it is saidThen
a value refused - not a number, out of the type's range, out of the limits, missingstdout, with the program's name: myserver: value 0 for option '--port' is inferior to its lower limit. Allowed range: 1-65535corArgsParse returns the status
an unrecognized optionstdout, myserver: unrecognized option: -x, and the usageexit 1, inside corArgsParse
a required option not setstdout, myserver: missing required option: --file, and the usageexit 1, inside corArgsParse
a letter twice in a groupstdout, myserver: repeated boolean option: -nexit 1, inside corArgsParse
a fault of the table, a value refused on the command linethe error list, and a line on stderr through corBase's library log (E: corArgsParse.c[<line>]: corArgsParse: CorArgs Error ...)the status is returned

The error list is corArgsErrorGet(), newest first - each CorArgsError with the file, line and function that pushed it, the option's name, errno, the status and a description:

for (CorArgsError* eP = corArgsErrorGet(); eP != NULL; eP = eP->next)
  fprintf(stderr, "%s[%d] %s: %s - %s\n", eP->fileName, eP->lineNo, eP->funcName, eP->optionName, eP->description);

A refused value of the environment is said and returned, not pushed. coraine stops on any status that is not CorArgsOk: corArgsParse failed: invalid value, exit 1.
