corBase

The library every other library of the stack stands on: the library log through which a library writes into its executable's log, the coroutines and their event-loop waits, and the small helpers - strings, files, time, the process's CPU and memory limits - that would otherwise be copied into each library.

What is in it

One function, or one small family, per header, included as "corBase/<header>.h":

The library log

A library cannot know where its executable logs - a file, which one, in what format - so it does not log itself: it hands every line to a function the executable gives it.

typedef void (*CorLibLogFunction)(const char* fileName, int lineNo, const char* functionName,
                                  char type, int aux, const char* format, ...);

void corBaseInit(CorLibLogFunction logFunction);
void corBaseTraceLevelsSet(const unsigned int* levelV, unsigned int words);

The signature is corLog's corLogOut. type is 'E', 'W', 'I', 'V', 'T' or 'X'; aux the trace level of a 'T', the exit code of an 'X', -1 otherwise. An executable that logs with corLog wires it up once its log is open:

corBaseInit(corLogOut);
corBaseTraceLevelsSet(corLogTraceLevels, sizeof(corLogTraceLevels) / sizeof(corLogTraceLevels[0]));

In the library:

Macro
COR_LIB_E(fmt, ...)error
COR_LIB_W(fmt, ...)warning
COR_LIB_I(fmt, ...)info
COR_LIB_V(fmt, ...)verbose

COR_LIB_X(code, fmt, ...)an 'X' line, then exit(code)
COR_LIB_RE(ret, fmt, ...)error, then return ret;
COR_LIB_RVE(fmt, ...)error, then return;
#include "corBase/corLibLog.h"

#define MyLibTraceOpen  500                        // a level of this library's own range

int fileOpen(const char* path)
{
  int fd = open(path, O_RDONLY);

  if (fd == -1)
    COR_LIB_RE(-1, "open(%s): %s", path, strerror(errno));

  COR_LIB_T(MyLibTraceOpen, "%s: fd %d", path, fd);
  return fd;
}
  • Before corBaseInit a line goes to corLibLogFallback: an error, a warning or an exit is written to stderr as E: file[line]: function: message - option parsing runs before any log file exists - and everything else is dropped.
  • What is written is the executable's decision: the log function tests its own switches (corLogOut drops a V line when verbose is off).
  • A trace that is off is decided inline once corBaseTraceLevelsSet has handed corBase the executable's trace-level bitmask - read in place, so a level changed at run time is seen at once. Without it every COR_LIB_T is a call into the log function, which then says no.
  • In a release build - no -DCOR_T_ON - COR_LIB_T is compiled away, its arguments still type-checked. An object compiled with COR_T_ON carries the string COR_T_ON:traces-compiled-in (corLog - release builds).
  • The trace levels are the executable's number space, shared by every library: each takes a range of its own (the ranges in use).

Coroutines

corCo runs a function on a stack of its own that can stop half way and be continued later, on the same thread. The switch is corBase's own - the callee-saved registers and the stack pointer, in assembly, for x86-64 and aarch64; any other architecture does not compile. Each stack is 256 KiB of address space, MAP_NORESERVE, with a guard page below it; a finished coroutine's stack goes back to a pool of its thread's (up to 256 kept) and the next coroutine takes it.

static void counter(void* arg)
{
  int n = *(int*) arg;

  for (int i = 1; i <= n; i++)
  {
    printf("step %d\n", i);
    corCoYield();                                  // back to the resumer
  }
}

static void counterRun(void)
{
  int    n   = 3;
  CorCo* coP = corCoCreate(counter, &n);

  if (coP == NULL)
    return;

  while (corCoResume(coP) == false)                // true once counter has returned -
    printf("yielded\n");                           // its stack is back in the pool then
}
Call
corCoCreate(fn, arg)a coroutine that runs fn(arg) when first resumed; NULL when out of memory
corCoResume(coP)runs it until it yields or returns; true when it has finished - coP is gone then
corCoYield()back to whoever resumed it; nothing outside a coroutine
corCoDestroy(coP)one that will never be resumed: its stack back to the pool, nothing on it unwound
corCoCurrent(), corCoUserDataSet/corCoUserDatathe running coroutine; one pointer for the caller

corCoLoop puts coroutines on a thread's epoll loop: a coroutine that needs a descriptor ready calls corCoLoopWait(fd, events, timeoutMs, &revents) - it registers the descriptor and yields, and the loop resumes it when the descriptor is ready or the time is up. Outside a coroutine of a loop it is poll(). The loop's side is corCoLoopInit once, corCoLoopTimeoutMs for its epoll_wait, corCoLoopEvent for each event and corCoLoopExpire after them; corCoLoopPark/corCoLoopWake let a coroutine wait for another, corCoBlocking runs a call that blocks in another library on a thread of its own, and corCoLoopCancel ends every wait when the loop stops.

A coroutine belongs to its thread - it is resumed there only - and never yields with a lock held: another coroutine of the thread that wants the lock waits for ever, since the holder cannot run. corCoBlocking's function runs on another thread and must not touch the caller's thread-bound state.

Strings, in place

The string helpers allocate nothing; several write into their input.

  • corStringSplit(s, d, sVec, sVecLen) replaces each delimiter in s by a 0 and points sVec into s: s must be writable, and is changed. It returns the number of items, stopping at sVecLen; an empty or NULL string has 0.
  • corStringSort sorts a string's characters in place.
  • corStringReplace and corStringArrayJoin write into the caller's buffer and stop when it is full - the result is cut, NUL-terminated.
  • corProgName(argv[0]) returns a pointer into its argument, after the last /.
  • corFileSuffixExtract(name, len, destructive): destructive, the . becomes a 0 and the pointer is into name; else a strdup, the caller's to free.
char  list[] = "220-226,403";
char* itemV[8];
int   items  = corStringSplit(list, ',', itemV, 8);   // 2: "220-226", "403"

Building

make                  # BUILD=debug (with -DCOR_T_ON): libcorBase.a, libcorBase.so, obj/debug/corBaseTest, the tools
make BUILD=release    # without COR_T_ON
make install          # the same, and the tools into bin/
make arm64-test       # the smoke test built for aarch64, run under QEMU

Consumers compile with -I.. and link ../corBase/libcorBase.a from the checkout. The tools - atoh, atoi, htoa, htoi, itoh - are small hex, ASCII and integer converters.
