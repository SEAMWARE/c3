corHash

A chained hash table keyed by a string. The caller supplies the hash function and the compare function, and the table stores only a pointer to the caller's item - the key is read from the item, never copied. Its memory comes from malloc or from a corAlloc arena, chosen per table. Repository: SEAMWARE/corHash.

The model

A table is an array of slots list heads. An item added is a CorHashListItem - the item's pointer, the hash code of its name, the next item - put at the head of its slot's list. A lookup hashes the name, walks that slot's list, and calls the compare function only on an item whose cached hash code is the same.

  • The slot is hash & (slots - 1) when slots is a power of two, else hash % slots.
  • The table never grows and never rehashes: slots is fixed at creation, and a table holding many more items than slots has long lists.
  • It takes no lock: a table changed by one thread and read by another needs the caller's lock.

The two functions the caller supplies

typedef unsigned int (*CorHashCodeFunction)(const char* name);
typedef int          (*CorHashCompareFunction)(const char* name, void* itemP);

The compare function gets the name looked up and an item of the table, and returns 0 when the item is the one with that name. It reads the key from the item - so the key must stay valid, and unchanged, as long as the item is in the table. From src/lib/serviceRoutines/getEntities.c, a table of entities (corTree nodes) by id:

static unsigned int idHash(const char* name)
{
  unsigned int h = 5381;

  while (*name != 0)
    h = (h * 33) ^ (unsigned char) *name++;

  return h;
}

static int idCompare(const char* name, void* itemP)
{
  CorNode* idP = corTreeLookup((CorNode*) itemP, "id");

  return ((idP != NULL) && (idP->type == CorString)) ? strcmp(name, idP->value.s) : 1;
}

static CorHashTable* idHashCreate(CorNode* arrayP, int n)
{
  int slots = 1024;

  while ((slots < n) && (slots < (1 << 20)))
    slots *= 2;                                         // a power of two: a mask, not a modulo

  CorHashTable* hashP = corHashTableCreate(&corRest.kalloc, idHash, idCompare, slots);

  if (hashP == NULL)
    return NULL;

  for (CorNode* eP = arrayP->value.head; eP != NULL; eP = eP->next)
  {
    CorNode* idP = corTreeLookup(eP, "id");

    if ((idP != NULL) && (idP->type == CorString))
      corHashItemAdd(hashP, idP->value.s, eP);
  }

  return hashP;                                         // freed with the request's arena
}

Rules

corHashItemAdd does not look first. Adding a name that is in the table already adds a second item: a lookup finds the newer one (it is at the head of the list), a remove unlinks the newer one and the older one is found again. A caller that wants one item per name looks it up before adding.

  • Choose the allocator by the table's life. In an arena, a removed item's memory stays allocated until the arena is reset; a table with many adds and removes over a long life belongs on malloc. coraine's per-request tables are in the request's arena; corDB's history tables and coraine's bridge channel cache, which live as long as the process, are on malloc.
  • Growing is the caller's. A table that has to grow is replaced: a new table with more slots, every item added to it, the old one released - corDB's history index does this when it doubles.
  • The hash function is the table's. corHashItemCustomLookup changes only the compare function; an item found by another key needs corHashItemLookupInAllSlots, which costs a compare per item.
