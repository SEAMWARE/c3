corJsonld

The JSON-LD layer of the broker: it parses @contexts, keeps them in a cache, downloads the ones it has not seen through a callback, and expands and compacts the names and values of a parsed tree - term by term or a whole body in one pass. It never opens a socket, and it knows NGSI-LD only as far as the core context goes: the NGSI-LD rules sit above it, in corNgsild.

The model

ThingWhat it is
CorLdItemone term: its short name, its expanded id, its @type ("@id", "@vocab", "@json", a datatype, or NULL), its parsed @container (a bit of CorLdContainer), the KJF_* flags and, for a core term, the caller's termId
CorLdContextone parsed @context: a name table (expansion) and an IRI table (compaction), its @vocab, or - for an array @context - its child contexts. Plus what the cache needs: url, id, the raw body, its kind (CorLdKindImplicit, CorLdKindCached, CorLdKindHosted - NGSI-LD § 5.13.1), timestamps
the core contextthe NGSI-LD core context v1.9, compiled in (corLdCoreContextBody.h, CORLD_CORE_CONTEXT_URL). It always takes part in an expansion, and it wins over every user context
the cacheone per process: every context downloaded, hosted or minted, found by URL or id

Everything works on corTree's CorNode trees, as corJson parses them, and allocates from a corAlloc arena the caller passes in. The umbrella header corJsonld/corJsonld.h includes the rest.

Starting it

int corLdInit(CorAlloc* kaP, const char* coreContextUrl, CorLdDownloadFunction downloadFn, CorLdErrorFunction errorFn);

typedef char* (*CorLdDownloadFunction)(const char* url, int* statusCodeP);
typedef void  (*CorLdErrorFunction)(int status, const char* title, const char* detail);
Argument
kaPthe cache's allocator, for the life of the process: every cached context - downloaded, hosted, the core - lives in it. Several threads allocate into it at once, so it must be thread-safe (corAllocThreadSafe). coraine's is a 64 KiB static buffer with 256 KiB blocks
coreContextUrlNULL or CORLD_CORE_CONTEXT_URL: the compiled-in core. Any other URL is downloaded through downloadFn. coraine passes NULL
downloadFnfetches a remote @context: returns a malloc'd body (the library frees it) and sets *statusCodeP; anything but 200 is a failure. NULL: inline contexts only
errorFntold why a context it could fetch cannot be used, as an HTTP status, a title and a detail (below). May be NULL

It returns 0, or -1 - also when the core context declares no @vocab: without one, a name no context defines could not be expanded at all, so it refuses to start. A second call is a no-op; corLdCleanup() resets the library's state.

A broker that adds terms of its own to the core, or numbers the core terms, does it right after:

corLdInit(&contextAlloc, NULL, startupContextDownload, startupContextError);
corLdCoreTermsAdd(termV, &contextAlloc);                        // { name, type } ..., { NULL, NULL }
corLdCoreTermIdsSet(nameV, count, &contextAlloc, &missing);     // once, after every corLdCoreTermsAdd

This is coraine's order (src/lib/startup/startupCoreContext.c): corLdInit, the terms of its bridge payloads and of its NGSI-LD extensions, then corNgsild's ldCoreTermIdsInit, which calls corLdCoreTermIdsSet with the CorTerm names (the core context).

Parsing a context

CorLdContext* corLdContextFromTree(CorNode* contextNode, CorAlloc* kaP, const char* baseUrl);
CorLdContext* corLdContextFromObject(CorNode* objectNode, CorAlloc* kaP, const char* url);
CorLdContext* corLdContextFromUrl(const char* url, CorAlloc* kaP);

corLdContextFromTree takes the VALUE of an @context member - a string, an object or an array of them. A string is a URL: resolved against baseUrl when it is relative (corLdUrlResolve, RFC 3986 § 5; NULL for a context that arrived inline, which leaves it as it is), then fetched with corLdContextFromUrl. An array becomes a context of child contexts, searched last to first: a later definition wins. An element that cannot be had fails the whole array - NULL.

In a context objectWhat happens
"t": "iri", "t": { "@id", "@type", "@container" }a term; a term object without @id maps to its own name; a prefix:suffix id is expanded with the context's own prefixes
@vocabkept on the context - but only the core context's @vocab is used to expand (below)
@version, @protectedskipped
@importNULL, and errorFn(501, ...) - not implemented
a term with an @context of its own (a scoped context)NULL, and errorFn(400, "Scoped Context Not Allowed", ...) - except in the core context, which has one (ngsildproof)

The cache and downloads

corLdContextFromUrl looks in the cache first. A miss is downloaded, parsed into the cache's allocator (the caller's kaP holds only the parse tree), marked CorLdKindCached, its body kept for GET /jsonldContexts/{id}, and inserted. A downloaded @context whose @context is a string is followed to that URL.

Rule
the keythe id or the URL, compared without the scheme: http://h/x and https://h/x are one entry, the first one seen
size100 entries; past that the entry used longest ago is dropped (LRU on usedAt, refreshed by every lookup)
memorynever freed: corLdCacheRemove and the reaper unlink an entry, its memory stays in the allocator
older core contexts.../ngsi-ld-core-context.jsonld and ...-v<N>.<M>.jsonld other than the configured one are not downloaded: they are cached as a stub with ignored set, which every lookup skips - the broker's own core stands. corLdIsCoreContextUrl says true for all of them
one download per URLup to 16 URLs (CORLD_MAX_DOWNLOADING) are tracked while they download. A second asker for one of them waits for it - 150 polls of the cache, 20 ms apart, 3 s in all - and gets NULL if it has not landed. Past 16 in flight, a download is not tracked and may happen twice
a cyclethe asker that is itself downloading the URL - an array @context that leads back to itself - gets NULL at once, with errorFn(400, "Cyclic @context", url)
volatile contextsvolatileCtx, expiresAt: a context the broker mints so a Link header can name an inline body by URL. Not dropped when fetched; corLdCacheReapVolatile(now) unlinks those past expiresAt (corNgsild runs it every second, ldContextHost.h)

The rest of the cache API - corLdCacheLookup, corLdCacheInsert, corLdCacheRemove, corLdCacheSnapshot (the entries in insertion order, pointers into the cache, not copies) and corLdIdGenerate (a Hosted context's id, urn:ngsi-ld:Context:<counter>-<epochSeconds>, unique within one run) - is what the broker's /jsonldContexts endpoints are built on.

Failures

corLdContextFromUrl answers NULL for every failure. The ones that are not "could not be retrieved" - a cycle (400), a scoped context (400), @import (501) - also go to errorFn, so the caller can tell them apart. coraine's turns them into ProblemDetails (400 BadRequestData, 501 a type of its own); a NULL with no call is answered by coraine as 504 LdContextNotAvailable.

Expansion

char* corLdExpand(CorLdContext* contextP, const char* name, CorAlloc* kaP, CorLdItem** itemPP, bool* coreContextP);

One name, in this order - the first step that answers wins:

#The nameBecomes
1already an IRI (urn:, http://, https://) or an @-nameitself - unless it is a core term's IRI: then the term's short name (@id and @type are the IRIs of id and type)
2prefix:suffixthe prefix's IRI + suffix, the user context's prefixes first, then the core's; a core term's IRI again becomes its short name
3a term of the core contextits short name - the core wins: a user context cannot redefine type, value, observedAt, ...
4a term of the user contextits IRI
5anything elsethe core @vocab + the name: speed is https://uri.etsi.org/ngsi-ld/default-context/speed. A user context's @vocab is not used

*itemPP gets the matched CorLdItem (NULL when no item answered), *coreContextP true when the core answered; both may be NULL. Before step 5 the name goes through the vocab-expand check, if one is set (callbacks): rejected, the answer is NULL. corLdExpandValueKey is the same without that check - for member names inside a compound value, a language map's tags, a q trailing path.

A whole body

CorLdContext* corLdExpandTree(CorNode* treeP, CorLdContext* userContextP, CorAlloc* kaP);
CorLdContext* corLdExpandEntityTree(CorNode* treeP, CorLdContext* userContextP, CorAlloc* kaP);

Renames every member of the tree in place and returns the context it used. A body's own @context (the root of an object, each element of an array) is parsed, used for its subtree instead of userContextP, and removed from the tree. NULL userContextP is the core context. On the way:

  • a member whose term is @type: @vocab has its string values expanded too (watchedAttributes, propertyNames, valueType, ...); type's values are expanded; @type: @id values are left alone
  • a scalar value of a term with a datatype @type, and the @value of a value object {"@value", "@type"} outside an Attribute's value, go to the value-check callback
  • nothing is expanded inside an @language or @index container's keys, a json member, a term typed @json, or a JSON literal {"@type": "@json", ...}; an @index map's values are expanded
  • a member name starting with @ that is not a JSON-LD 1.1 keyword (corLdKeywordIs) goes to the keyword-check callback, which may stop the expansion
  • a node already stamped with a core termId (by a parser hook) is not looked up again

corLdExpandEntityTree also does JSON-LD array reduction: a one-element array becomes its element, unless its term keeps arrays (@list, @set, @language, @json). It is for entity data only - an API object (Subscription, Registration) keeps its arrays.

Compaction

const char* corLdCompact(CorLdContext* contextP, const char* iri);
void        corLdCompactTree(CorNode* treeP);                            // with the core context
void        corLdCompactTreeWith(CorNode* treeP, CorLdContext* ctxP);   // with this one
#corLdCompact tries
1not an IRI: returned as it is
2a term of the user context with this IRI: its name
3a core term with this IRI: its name
4starts with the core @vocab: the rest - unless that name is a term of another IRI
5only when 4 was refused for that reason: prefix:rest, the longest prefix of the user or core context
6the IRI, unchanged

The tree functions mirror the expansion: names, type values, @vocab-typed values, the same opaque containers. The answer is a pointer into the IRI, the item, or a new string allocated from corRest.kalloc (step 5) - see pitfalls.

The core context

Every core term is stored, matched and rendered by its short name: at init the core context's ids are rewritten to their names (keyword ids - id is @id, type is @type - are kept), so corLdExpand("observedAt") answers "observedAt" with no extra work. Its @vocab is https://uri.etsi.org/ngsi-ld/default-context/, in corLdCoreVocab / corLdCoreVocabLen.

The rewrite leaves the working copy without its own IRIs, so the library parses the core a second time and keeps that one as it is: corLdCorePristine(). Anything that needs a real core IRI reads it there.

Function
corLdCoreContext()the working core context
corLdCoreLookup(name)the core item a name denotes - short name, IRI, ngsi-ld: compact IRI, @id/@type - or NULL; no allocation. For a parser that must know at once whether a member is a core term
corLdCoreItemByIri(iri)the core item with that expanded IRI, or NULL
corLdCoreItemById(termId)the core item with that termId - an array index; NULL for 0, out of range, or before corLdCoreTermIdsSet
corLdCorePrefixes(&n)the core's prefix terms (ngsi-ld, geojson), with their IRIs
corLdCoreTermsAdd(termV, kaP)makes terms of the caller's own payloads core terms - short, never expanded, never overridden. A term the core has is left as it is. Returns the number added, -1 on error
corLdCoreTermIdsSet(nameV, count, kaP, &missing)nameV[id] is the name of term id (1 <= id < count, at most 0x10000). Stamps each core item and its pristine twin. A core term left without an id is -1, its name in *missing: the table does not match the core

A term added with corLdCoreTermsAdd shadows that name in every vocabulary a client loads - the core overrides every other context. Pick names that the well-known vocabularies (Smart Data Models, schema.org, SOSA/SSN, SAREF) do not use.

The flag bits it sets

At init each core item gets its KJF_* bits (corLdExpand.h); the expander ORs the matched item's bits onto the node (CorNode.flags) and copies its termId - so the layer above tells a structural member from a sub-attribute with a bit test.

BitsSet on
KJF_CORE_TERM 0x01every core term - and a name expanded with a core prefix that names no term
KJF_ATTR_TERM 0x02the members of an Attribute that are not sub-attributes: the seven value keys, type, observedAt, expiresAt, unitCode, datasetId, valueType, objectType
KJF_VK_* bits 4-7which value key, read with KJF_VK_ID(flags): 1 value, 2 object, 3 languageMap, 4 vocab, 5 valueList, 6 objectList, 7 json; 0 none

A user term's item has no bits and termId 0 - the node keeps whatever a parser stamped.

They are plain globals: set them once, at startup, before the first request. corNgsild's ldInit() sets the first four.

Concurrency

The cache is guarded by one mutex, held only for a lookup, an insert or a removal - never across a download or a parse. A download is owned by whoever started it: another asker waits, the same asker again is a cycle. By default the asker is the thread (pthread_self) and the wait is usleep. An application that runs several requests on one thread says otherwise:

typedef uintptr_t (*CorLdOwnerFunction)(void);
typedef void      (*CorLdSleepFunction)(int ms);
void corLdConcurrencySet(CorLdOwnerFunction ownerFn, CorLdSleepFunction sleepFn);   // NULL: the default

coraine's (src/app/coraine/coraine.c), so that a coroutine waiting for another's download yields instead of stopping its loop:

static uintptr_t contextOwner(void)
{
  CorCo* coP = corCoCurrent();

  return (coP != NULL) ? (uintptr_t) coP : (uintptr_t) pthread_self();
}

static void contextSleep(int ms)
{
  corRestWaitFd(-1, 0, ms, NULL);   // no descriptor: a timer - a yield in a coroutine, poll() elsewhere
}

corLdConcurrencySet(contextOwner, contextSleep);   // before corLdInit, before the first request

An example

#include "corAlloc/corAlloc.h"           // CorAlloc, corAllocBufferInit
#include "corJson/corJsonCreate.h"       // CorJson, corJsonCreate
#include "corJson/corJsonParse.h"        // corJsonParse
#include "corTree/corTreeLookup.h"       // corTreeLookup
#include "corJsonld/corJsonld.h"

int main(void)
{
  static char buf[65536];
  CorAlloc    ka;

  corAllocBufferInit(&ka, buf, sizeof(buf), 65536, NULL, "jsonld");
  if (corLdInit(&ka, NULL, NULL, NULL) != 0)            // the embedded core; inline contexts only
    return 1;

  char     json[]   = "{ \"@context\": { \"temperature\": \"https://example.org/temperature\" } }";
  CorJson  corJson;
  CorJson* corJsonP = corJsonCreate(&corJson, &ka);
  CorNode* docP     = corJsonParse(corJsonP, json);       // destructive: parses json in place

  CorLdContext* ctxP = corLdContextFromTree(corTreeLookup(docP, "@context"), &ka, NULL);

  char*       iri   = corLdExpand(ctxP, "temperature", &ka, NULL, NULL);   // "https://example.org/temperature"
  char*       other = corLdExpand(ctxP, "speed", &ka, NULL, NULL);         // ".../default-context/speed"
  const char* name  = corLdCompact(ctxP, iri);                               // "temperature"

  corLdCleanup();
  return 0;
}

It links with libcorJsonld.a and the libraries below it - and with corRest, whose corRest.kalloc corLdCompact refers to.

Rules and pitfalls

  • Pass the value of @context to corLdContextFromTree, not the document that holds it.
  • The cache allocator is shared and must be thread-safe; the kaP of the other calls only holds what lives as long as the call's result is used (an expanded name, a parse tree).
  • corLdCompact's compact-IRI form (step 5) is allocated from corRest.kalloc, the calling thread's corRest arena: a thread that is not corRest's sets one up first.
  • Never read a core IRI off a working-copy item - its id is its name. Ask corLdCorePristine() or corLdCoreItemByIri.
  • A cache entry is never freed; a pointer from corLdCacheSnapshot stays valid until the entry is evicted.
  • Trace levels are 150-156 (corLdTraceLevels.h: init, parse, expand, compact, cache, download, prefix).
